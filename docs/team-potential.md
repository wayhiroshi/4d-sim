# チームの配下ポテンシャル（Strategy Studio 2.2）

仮登録した人を選択し、将来の配下ポテンシャルを100・300・500 IDまたは任意の整数で指定する。空欄は従来どおり未設定、0は本人だけ。すでに組織図にいるメンバーも「この人の成長・ポテンシャルを設定」から個別の成長前提にできる（既存の12チーム上限内）。

- 本人を除く全階層の在籍ID数の上限として扱う。休止は含み、退会は除く。サブも1 IDとして数える。公式のタイトル判定人数とは別の入力前提。
- 最初の同行人数、成長開始月、毎月の紹介ペースは別の設定。上限の人数を即時追加したり、そこへ必ず到達するよう成長率を調整したりしない。
- 配下の別設定チームも上位チームの人数に含む。容量が埋まった枝への新規加入は止め、空きのある他の枝は成長を続ける。
- 配置変更・サブ繰上げ後の実際の試算ツリーで毎月判定。既存在籍数や明示的な移動・サブ作成によって上限を超えても既存IDを消さず、警告してその配下への新規加入を止める。
- 本人を選び直しても設定を表示。案A/B比較、Undo、保存リビジョンのrequestに含める。成長前提が変わった比較として表示する。
- 旧保存データはフィールド省略を許容し、従来の結果をそのまま表示。新計算・新保存はエンジン2.2.1で行う。D1スキーマ変更は不要。
- 未設定でも、計算期間・全体ID処理上限・チーム配分・資格条件は引き続き適用する。上限値は達成人数や収入の保証ではない。

## 最終組織ツリー（2.2.1）

- 最終形とチェックポイントは配置親に沿った枝線付きツリーに統一。名前の横の `(100)` は本人を除く全階層の在籍ID数で、休止中を含み退会済みを除く。稼働ID数は別表示する。
- 名前を押して配下を展開・収納しても合計人数を表示する。表示を省略したIDは「その他の配下」に集約し、親子の合計を二重加算しない。
- 主要チームへの接続に必要な途中のIDも保持する。旧保存結果で接続情報がないチームは別表示し、架空の親子関係を作らない。再計算で新形式へ更新できる。
- 114テスト、型チェック、本番用ビルド成功。匿名データによるPC・390px幅で合計表示、展開・収納、横はみ出しがないことを確認済み。
- 2026-09-25、ユーザーの「公開OK」によりポテンシャル入力とツリー表示を合わせてリリース対象とする。DBマイグレーションは不要。
