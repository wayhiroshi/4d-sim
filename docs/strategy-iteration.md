# Strategy Studio 2.4 — 同じ月の組織・金額を直接比較

## 2.4 の変更

- 主画面は結果バー、月スライダー、編集ツリーに集約。候補探索・保存一覧・前提設定は「その他」、金額は「金額の内訳」から開く。
- 各月に組織スナップショットを保持し、月額・タイトル・配下人数を同じ月で表示する。旧保存結果に月別組織図がない場合、未来の組織図を流用せず再計算を案内する。
- 変更前との差は直前に完了した案の同じ月と比較する。計算中は古い金額・タイトルを新配置の結果として表示しない。
- 組織ページは保存済みタイトルとは別に、仮配置・購入を反映して下位から当月タイトルを判定する。LDの達成・未達が配置変更後に表示へ反映される。DBの取得履歴は変更しない。
- 優先育成は LD/DR の浅い段の構成不足から埋める。新規紹介IDの割当と、優先IDのGコース・ライセンス取得予定は利用者が明示して比較する。既存の資格取得予定を上書きしない。移動操作で紹介ID方針を解除しない。
- 4,001 IDでもコース・ライセンス不足ならDR未達となるケースを固定テストにし、人数だけで昇格させない。不足理由は具体的に表示する。
- 2,000 ID/120か月の既存ベンチマークは今回約4.9〜5.2秒（開発端末、候補2件）。5秒以内を保証するものではない。

以下は引き続き利用する候補比較の仕様。

## 目的と操作

配置・所有IDの育成順を小さく変え、同じ成長前提の月額と到達期間を比較する。

- 配置を変更するとその1案を再計算する。元に戻す・やり直すは直近20操作。新しい編集でやり直し履歴を破棄する。
- 「選んだチームの配置先を比較」：チームを一体として、現在の自分・パートナー・各所有サブの配下へ移す。循環・1次ライン上限違反を除外。
- 「メイン・サブの育成順を比較」：所有者本人の成長前提がある場合、所有IDを1個または2個の順でDRまで優先。取得した翌月に次へ、完了後は本人へ戻す。既存メンバーは動かさず、人数も増やさない。紹介者の選択可否は入力設定に従う。資格・紹介条件を自動付与しない。
- 「チームの組合せも探す」：独立した新規チームの配置を比較。内部の子チームはそのまま保持。
- 全案の金額を同じ経過月（入力の計算年数）・選択した成長前提で比較。継続月額、購入費控除後の参考月額、現在案との差、目標タイトル到達月、ID別内訳を表示する。
- 採用後に既存の「別案として保存」を利用。優先順を含め、入力・出発点・全成長前提の結果を不可変リビジョンとして保存する。

## 計算範囲

- 小さい新規チーム×所有IDの配置空間（64通り以内）は全列挙し、配置制約で絞る。
- 大きい空間は所有IDへの集中・分散案を計算し、実際の金額・到達月で上位3案を選ぶ。その1チームを動かした近傍を追加。合計最大96候補、1回の追加探索。
- 従来の候補生成も小空間では全列挙。大空間の24件ビームに加えて、各所有IDへの全チーム集中案を必ず残す。
- 同額・同月は入力のIDを含む安定したキーで順位を固定する。
- 探索範囲内の比較であり、全組織・全育成順・サブ新設削除まで含む大域最適解の保証ではない。組合せ探索と育成順探索は別操作。

## 応答性と保護

- 操作中の計算はブラウザWeb Workerで実行。比較候補は選択した1成長前提だけを計算し、途中結果から表示する。採用後は通常計算で3成長前提を揃える。
- 最新ジョブだけを表示し、古い計算を破棄する。元に戻す・ドラッグは計算中でも操作可能。比較の中止では計算済み候補を残す。
- 入力全体・出発点・エンジン版・成長前提・計算モードをキーに、Workerごと最大32件／推定24MBのLRUメモリキャッシュ。リロードや画面終了で消える。端末ストレージへ個人データは保存しない。
- 今版は差分サブツリーだけの再計算ではない。未計算の1案は月次ルールエンジンで再計算する。条件数・期間・端末によって待ち時間は変わる。
- 公開・DBマイグレーション・外部API・Workers AIの追加はない。

## 検証（ローカル・匿名データ）

- 3チーム×3所有IDの27配置を独立に列挙し、実報酬計算による最高参考月額と比較順位が一致。
- 集中サブ案、禁止配置、入れ子チーム、育成段階の取得後切替、所有者分離、同じ入力の再現性をテスト。
- キャッシュの再利用・上限、最新ジョブ優先、単一前提と採用後の通常計算の一致、D1保存復元をテスト。
- 全体テストの2,000 ID／120か月／3戦略×3前提の既存ベンチマークは約4.8秒（候補2件・開発端末）。大量候補探索や本番端末の応答時間を保証する数値ではない。
