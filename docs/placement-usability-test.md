# 配置を試す：理解度チェック用の試作品

入口：`/try`。匿名サンプルのみ。APIへの保存・実組織の変更・永続キャッシュはしない。
既存の `/organization`、`/simulator` と保存済みプランはそのまま残す。
金額・タイトルは既存エンジンの standard / preview で計算する。比較は直前の操作のみ。

## 参加者に渡す課題

画面の使い方を先に説明せず、次の課題だけを一つずつ渡す。

1. 新しく参加するCさんは、将来100 IDくらいの組織になると考えています。自分のサブの下に置いた場合を試してください。
2. Cさんを自分のメインの下に置いた場合と比べてください。10年後の月額はどちらが大きいですか？ TRDまでの時間について何が分かりますか？
3. 一つ前の配置へ戻してください。ここで実際の会員登録は変更されたと思いますか？
4. 自分のサブのDR取得を優先する場合へ切り替えてください。DRになる時期と月額の違いはどこで分かりますか？ 現在のタイトルまでDRに書き換わったと思いますか？

サブの「今のまま／DRを優先」は将来の育て方を変える選択。DR優先時は、所有者の今後の紹介をサブ側へ振り分け、取得条件に沿って配置する。現在のタイトル・紹介関係は変えず、条件を満たした月からエンジンがタイトルを判定する。操作は「一つ前に戻す」で取り消せる。

既存メンバーを試しに追加した人の下へ移す場合は、その人が加入した月に配下ごと移動する。加入前の月は元の配置を表示する。既存メンバーの紹介者・所有者・成長前提は変えない。

追加の種類は「通常のメンバー／自分のサブID」。サブは現在と追加予定の合計5 IDまで。翌月作成・Gコース・12か月後のライセンス取得を前提に、自分の収入と購入費に合算する。サブ自体に独立した紹介能力は加算せず、配下の配置やDR優先で育てる。各サブのDR優先は別々に切り替えられ、最後に優先したサブから順に育てる。

## 観察者用

- 実際に初めて使う会員を目安5名。実在メンバーや収入データは見せない。
- 操作が止まった箇所、読み違えた言葉、最初に押した場所、助言が必要だった操作を記録。
- 「分かりましたか」ではなく、「この金額は誰の、いつの、何を含む金額ですか」と自分の言葉で説明してもらう。
- TRD未達を「絶対になれない」と解釈していないか、仮定による結果と理解しているか確認。
- まず全員が、助言なしで追加・移動・取り消しを完了できることを目指す。
- 実施日・参加人数・観察結果は実施後に記録。AIや開発者の操作確認を第三者テスト成功と扱わない。
